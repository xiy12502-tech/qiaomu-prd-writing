# 证据与不确定性规则

## 五类信息

| 类型 | 定义 | 写法 |
|---|---|---|
| 已确认事实 | 用户明确提供、正式资料写明或可核验的事实 | 正常陈述，必要时注明来源 |
| 来源证据 | 研究、数据、会议结论、政策或外部材料 | 标注来源、日期或可追溯位置 |
| 合理推断 | 根据已知事实推导，但未获确认 | `【假设】` + 推断依据 + 错误影响 |
| 方案建议 | 作者提出的产品判断或取舍 | `【建议】` + 理由 + 替代方案/代价 |
| 待确认 | 缺失且影响方向、范围、验收或上线的信息 | `【待确认】` + 负责人/时点（若已知）+ 影响 |

## 不得自动补全

- 市场规模、用户比例、转化率、活跃度、性能阈值和日期；
- 用户访谈结论、竞品能力、法律/政策要求；
- 负责人、资源承诺、研发可行性和上线时间；
- “行业标准”“用户普遍需要”等无来源判断。

可提供建议值，但必须写为建议，并说明需要谁验证。示例数据只能用于解释格式，必须标注“示例，不代表真实目标”。

## 冲突与版本

- 来源冲突时不要自行选边：列出冲突内容、来源、可能影响和待决策人。
- 更新 PRD 时保留关键决策轨迹，写清变更原因和影响范围。
- 审查既有 PRD 时，将原文中的未经证实结论指出，不把它们继承为新事实。

## 外部检索

只有用户要求检索、核验或提供引用时才主动搜索外部信息。搜索结果应优先使用一手和权威来源，并把事实、推断和建议分开。找不到证据时明确写“证据缺失”，而不是用常识补齐。
